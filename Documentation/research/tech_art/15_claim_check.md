## Extra finding while checking claim 8 (INFERENCE from URP 17.6 source, UNCONFIRMED at runtime)

- In a **player build**, a lamp created with `AddComponent<Light>()` and no `UniversalAdditionalLightData` sends soft-shadow value 1.0 to the shader, which is **Low** filtering (`ShadowUtils.SoftShadowQualityToShaderProperty`, `ShadowUtils.cs:648-658`; `Shadows.hlsl:139, 294-305`), not the asset's High (`m_SoftShadowQuality: 3`). Nothing in the player adds the component for these lamps: light layers are off (`FrontRooms_URP.asset:76`), so `ForwardLights.cs:696-699` never calls `GetUniversalAdditionalLightData()`, and project code adds it only for the station TV light and the stairwell lights.
- In the **Editor**, URP's light-extraction delegate (`UniversalRenderPipelineCore.cs:1624-1638`, `#if UNITY_EDITOR`) calls `GetUniversalAdditionalLightData()`, which adds the component with "Use settings from Render Pipeline Asset", so Editor and clone captures may show High filtering that a desktop player does not. Whether the delegate runs for these runtime lamps in Play mode is not confirmed.
- If true, the fix is small and is a desktop gain: add `UniversalAdditionalLightData` when the lamps are created (`FrontRoomsRoomStream.cs:1200`, `:2167`; `FrontRoomsMapWorld.cs:3717`; `FrontRoomsMapWorld.Pool.cs:725`) and leave it on pipeline settings. That gives the High filter while the bias kernel stays 2.5. Setting `softShadowQuality = High` explicitly would also raise the bias kernel to 3.5 (12.9 cm at 162°). Check first: a Mac player capture (Xcode frame capture or Frame Debugger attached to a dev build) of one shadowed troffer, reading `_AdditionalShadowParams[i].y`.
