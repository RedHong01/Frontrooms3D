## 0. Rules every package keeps

1. **A switch to today, the new look as default.** Every new term sits behind a uniform branch on a property whose today value returns the old arithmetic exactly (`UNITY_BRANCH if (_FR_SurfaceDetail > 0.5)`, a global float set by a static `FrontRoomsSurfaceDetail.On`, default true), and new maps go into new slots (`_DetailMap`, `_GlossMap`, ...), never into the slots today's path reads. Proof per package: one raw PNG pair with the switch off against today's build, 0 px over 1/255.
2. **Tiers.** Desktop Ultra / High (GlassRT where it exists): everything. Desktop Medium / Low: everything except the hex-tiling fetches and the detail normal's second fetch (both behind a quality global the package sets from `QualitySettings`; the URP assets stay 设置菜单's). iPhone / iPad: the same shader path, maps at the phone twins' half size, hex-tiling off; the rest stays (it is ALU, not bandwidth), measured on a device in the combined test. **WebGL: nothing changes** (`#if defined(SHADER_API_GLES3) || defined(SHADER_API_WEBGPU)` compiles the new branch out, as the cue ink does), RULES rule 5.
3. **What stays as Red picked:** C+2 hung paper (lapped seam, canvas emboss, suede mottle; `wall_material` §9) and its print (平面视觉 / 壁纸动态's art through `Tools/print`); the door grain from the scan (`door_wood`, option G); porcelain white tile .93/.95/.96, T1's grey-green grout .66/.70/.67, aqua course .40/.76/.77, porcelain abrasive deck (`70` §4.9, Red 13:10 "全部按推荐"); every zone's lamp (L03 at lens 1.8, O-C, R-B, P1-A / P2-A); walls never glow; the 1990 era lock (VCT, vinyl cove, broadloom and carpet tile, 2 x 2 acoustic ceiling, painted drywall and block, 6 in glazed tile, unglazed mosaic, laminate); "staged assets, not shader tricks": wear comes from generated or authored maps and decals that carry a cause, not from procedural cracks.
4. **Ownership (RULES rule 3).** Ours: `FrontRoomsSurface.shader` (the `_FR_TILE` block, the paper, the wear and the new detail terms), `Resources/Surfaces/*` materials and maps, `Tools/lookdev/*` generators, `Scripts/Rendering/PoolTile`, `Scripts/Rendering/GlassRT` and `NativePlugin` (the RT hit shader). Contracts: **关卡设计** for `Scripts/FrontRoomsMap/*` (the scene 4 tile swap in `FrontRoomsPoolMaterials.cs`; bevelled corners and edges in the map's geometry, `FrontRoomsMapWorld*.cs`, `Structures/*Kit*`, `*PoolTerrain*`, `*Well*`); **设置菜单** for any URP asset or quality-preset change (none planned: the tiers gate through our own globals). Shared file: `FrontRoomsSurface.shader` is also touched by the tech_art run (row 7: LOD cross-fade and the MotionVectors pass, pass headers and the fragment entry) and by the water runs (`FRWetBand`, the Submerged include, the waterline knob): every package here edits only its own functions, is built against main, and the parent rebases with `W/tools/rebase_apply.sh`.
5. **One glaze model in `FrontRooms/Surface`.** The level_space line's glaze (`research/level_space/73_pool_glaze.md`, landed 16:03; option sheet `glaze_options.jpg` with Red; shader prototypes `W/level_space/glaze/contract/glaze_b.diff`, `glaze_c.diff`, which apply clean on the clone's Surface c1a74c99) is folded into the tile package if Red picks one of its options, credited in the doc, not landed as a second model or a second contract.
6. **RT parity.** Any new term that changes albedo, smoothness or normal is mirrored in GlassRT's hit shader (`FrontRoomsGlassRT.metal`, material table in `FrontRoomsGlassRTSystem.cs`), or the RT glass shows today's surface; `_FR_TILE` gets its hit-shader port in the first package.

**Implementation notes for the build stage (tile path, `FRTileSurface`; all inside `UNITY_BRANCH if (_FR_SurfaceDetail > 0.5)` except P2's box-projection define, which is a compile-time define under `_FR_TILE` and therefore gets its own switch property `_TileBoxProj` read where the reflection vector is built):**
- *Cell and in-cell coordinates* exist (`cellF = floor(uv * _TileGrid.xy)`, the 192 m wrap). Add `f = frac(uv * _TileGrid.xy) - 0.5`.
- *Set and bow in the shader*, not the map (8-bit normal steps are 0.45 deg): `nTS.xy += tilt(cell) + bow(cell) * f * 2`, tilt Gaussian sd 0.25 deg clipped at 0.6 deg (GZ), bow as P1's numbers in edge-slope radians; scaled by the glaze mask so grout stays flat.
- *Joints (P3):* per row and column an offset `o = (h(i) - 0.5) * a` and per tile a width scale; `uvS = uv + delta(cell, f)`, continuous inside a tile, bounded so a joint never closes (min 1.5 mm); `SAMPLE_TEXTURE2D_GRAD(..., uvS, ddx(uv), ddy(uv))`.
- *Gloss (P4):* `mask.r += _TileGloss.x * (h(cell, 6) * 2 - 1)`, haze tiles `h(cell, 7) < _TileGloss.y` lower by 0.06-0.12; then P2's specular AA on the final normal.
- *Joint depth (P5):* cavity from the grout channel and the cushion slope feeds K3 and K4; K7's band beyond mip 2.
- *Phone:* the same code, `_Phone` maps; the second cube fetch of the two-lobe glaze off below iPad Pro if measured over budget. *WebGL:* compiled out.

Not recommended for the tile: POM on joints (3 mm joints at 2-4 mm per pixel: cost without a read past 1 m; K3 + K7 carry them), photo textures, POOLS' colours or rooms.
